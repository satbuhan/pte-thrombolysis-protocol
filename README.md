# Reperfusion Therapy in Acute Pulmonary Thromboembolism — Interactive Decision Algorithm

An interactive, referenced walkthrough of the decision-making algorithm for
thrombolytic and catheter-based reperfusion therapy in acute pulmonary
thromboembolism (PE). Every box and decision point in the diagram can be
selected to reveal, in one place: what the step means, why the algorithm
calls for it, the exact dosing as authored, and the sources behind it.

**Live site:** https://satbuhan.github.io/pte-thrombolysis-protocol/

**Authors:** Dr. Özgür Karcıoğlu & Dr. Satuk Buğra Han Bozatlı

## Why this exists

A flowchart alone tells a reader *what* to do at each step but not *why*,
and a reader outside the authors' own team cannot easily check the evidence
behind a specific number (a troponin-plus-severity-criteria threshold, an
alteplase dose, a resuscitation window). This page keeps the original
algorithm exactly as authored, and attaches the clinical reasoning and
literature to each box without cluttering the diagram itself.

The algorithm this page presents is Figure 1 of a narrative review by the
same authors, "Thrombolytic Therapy in Acute Pulmonary Thromboembolism: A
Narrative Review of Systemic and Catheter-Directed Reperfusion" (manuscript
in preparation, 73 references); the supplementary content on this page
draws on that review's evidence base, cross-checked against independent
sourcing for every citation.

## Status

This is a working version, built to be tested on both desktop and mobile.
Several things are worth flagging explicitly:

- **A structural ambiguity in the original Figure 1 was found and
  corrected before this tool was built.** An earlier draft of the figure
  drew only a NO arrow out of the "RV dysfunction on imaging AND elevated
  troponin?" box, with a "YES" label instead sitting on the arrow leading
  onward from "Anticoagulation alone" — readable either as a genuinely
  linear sequence or as a missing/mislabelled branch. Rather than resolve
  this unilaterally, it was flagged to the author team and checked against
  the manuscript's own text (Section 3's explicit "four sequential
  questions" framework), which confirmed the YES branch should bypass
  "Anticoagulation alone" entirely and pass directly to the severity-criteria
  question. Dr. Karcıoğlu subsequently sent a corrected figure implementing
  exactly this fix, with a caption now stating the branching logic
  explicitly — the version this tool is built from.
- **Reference 7 (Rosenfield et al., HI-PEITHO, NEJM 2026)** is used
  directly on two flowchart nodes ("Two or more severity criteria?" and
  "Activate PERT and consider reperfusion"). Independent verification
  confirmed the trial's headline results but surfaced two nuances not
  stated in the manuscript, preserved in those two nodes' own `rationale`
  text in `assets/content.js`: the trial's actual enrolment criterion
  combined respiratory rate and oxygen saturation into one item (so it
  required 2 of 3 independent criteria, not 2 of 4 as both the source
  figure and the manuscript present it), and PE-related death and
  all-cause mortality were numerically — though not significantly — higher
  in the catheter-directed-thrombolysis arm.
- **Reference 38 (Sadiq et al. 2017)** is cited by the manuscript as
  general supporting context for age and comorbidity predicting
  catheter-based-therapy bleeding risk. Independent verification found the
  source's own reported statistics (age p=.16, comorbidity p=.095) do not
  support that as a significant finding in that cohort — flagged in the
  reference's own `kind` field in `assets/content.js` rather than silently
  repeated. It is not used on any flowchart node.
- **Reference 50 (Ross et al. 2026)** could not be independently located
  or verified at all — its DOI did not resolve and no matching publication
  could be found elsewhere. It is not used on any flowchart node (the
  manuscript cites it only in passing) and is flagged as unverifiable
  rather than presented as confirmed.

All 73 manuscript references were independently re-verified against their
primary sources before inclusion. Everything else not flagged above is
paraphrased from a cited source, listed in the References section at the
bottom of the page.

This is also the first tool in the atlas whose source algorithm draws two
decisions' NO-branches sideways, in the same row, rather than below the
decision — "Anticoagulation alone" sits beside "RV dysfunction..." and
"Anticoagulation and close monitoring" sits beside "Two or more severity
criteria?", exactly as Figure 1 draws them. `assets/app.js` handles this
with the same named-group mechanism every other tool in the atlas uses for
a YES/NO pair, generalized to 3-wide and 4-wide rows (see `GROUP_COLUMNS`
and the `flow-wrap-3` / `flow-wrap-4` CSS classes) so that a decision and
its sideways terminal can share one explicit grid row without relying on
CSS auto-placement order.

## Disclaimer

This is an academic / educational reference tool, not a substitute for
institutional protocol or bedside clinical judgement. Verify any dose or
threshold against current local protocol before clinical use.

## How it's built

Plain HTML/CSS/JS, no build step and no framework — a single static site
that GitHub Pages can serve directly.

```
index.html          page structure
assets/style.css     design (the "paper" masthead/references,
                      the diagram scope + readout panel)
assets/content.js     ← single source of truth for every node's text,
                      dosing, and reference list. Edit this file to change
                      what the page says.
assets/app.js         rendering + interaction (builds the diagram and the
                      connector lines from content.js, handles the
                      click-to-expand panel on desktop and the bottom
                      sheet on mobile)
```

### Running it locally

No install needed:

```bash
python3 -m http.server 8000
# open http://localhost:8000
```

### Editing content

Open `assets/content.js`. Each entry in `NODES` is one box or decision
diamond from the algorithm (`meaning`, `rationale`, optional `dose` table,
and `refs` pointing at numbered entries in `REFERENCES`). Add or edit a
reference in `REFERENCES` and point to it by `id` from any node. Never
change a node's `label` or `sub` text without the author team's
sign-off — those fields are the algorithm itself, transcribed verbatim from
Figure 1. Every `sub` field carries the source box's own bullet points as
literal `\n` line breaks — preserve those exactly; they render as separate
lines, not flattened into comma-separated prose, because that is how the
original boxes are drawn.
